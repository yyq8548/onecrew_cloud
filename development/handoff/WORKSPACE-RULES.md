# 用户工作约定

随本次跨电脑交接保留的长期工作要求。项目范围和当前状态以 [AGENTS.md](../../AGENTS.md)、[GOAL.md](GOAL.md) 及用户最新明确要求为准。

## 工作范围与完成条件

- 开始前确认目标、交付物、完成条件和停止边界，只处理请求范围。设计一次考虑目标与约束，不用临时方案或工作量缩减要求；默认只提供一个满足要求的方案。
- 不自行切换 plan mode。执行已授权的必要工作；只在缺少必要信息、边界不明或平台规则要求时询问。已有授权持续有效。
- 用户以疑问句提问时只回答所问内容，不借机扩展或重新确认。工作中用户提问先及时回答，再继续尚未完成任务。
- 保持简单，先用满足当前需要的直接方案；只为明确输入、调用方、失败路径或已有承诺补机制。保留必要身份、权限、数据完整性、兼容性和恢复保障。
- 修改代码后运行相关检查，失败时修复后再验证，不要求用户代做可由代理完成的验证。人工身份、真实账号登录等必须由本人完成的步骤另行说明。
- 复用仍对最终状态有效的证据；交付完整、必要检查通过且范围内无已知阻碍后结束，不为重复验证而延长任务。
- 当前只改 Cloud；费用、方案和关键权限变化先审批。不要发送未经用户明确授权的外部邮件或消息。

## 指令与文档

- 指令应简洁、具体、长期适用，删除过时或重复要求。通用约定放入口，项目命令、架构和服务说明放最接近代码的文档；只在存在不同要求的目录增加更近层 AGENTS。
- 按任务读取资料，不要求每次修改前通读整个仓库或全部文档。详细条件通过明确入口按需读取。
- 用户可能修改或删除内容，修改前重读相关文件；保留当前状态，不自行恢复用户删除的内容。
- 用户指出错误后按纠正继续完成，最终内容保留正确状态。当前用户明确要求携带的历史失败记录仅用于追溯，不作为仍未修复的断言。

## 编码与工具

- 使用文件编辑工具直接修改代码；不使用 heredoc、Python、sed、Perl 或其他脚本改写源码，不在 Bash 命令中嵌入超长命令或多行脚本。
- 不使用 Git 回滚代码；需要恢复时通过文件编辑恢复目标内容。
- 不读写 `/tmp`。中间文件使用当前仓库中受忽略的 `.scratch`。
- 除用户明确要求外，不在 import 语句外使用 try/except；直接导入需要的库。采用 fast-fail，错误在发生处明确失败，不吞错或用 fallback 掩盖失败。
- 不使用 mock、伪造内容或只为通过检查设置的 workaround。合同输入、真实外部观测与回放证据必须明确区分。
- 需要第三方依赖时使用合适的依赖，不以减少依赖为目标，也不以自制替代品规避成熟库。成熟文件格式使用成熟解析库。
- 编写 Python 文件时不加开头 docstring 或 shebang；注释使用中文，专业术语保留英文，避免过度注释。
- 用户未明确请求视觉功能时不主动调用。

## 搜索与委托

- 文本和文件搜索优先使用 rg。用户提供网页链接时先读相关完整正文再开展工作。
- 页面因访问限制无法读取时，不猜测内容或换浏览器绕过；说明缺少内容，继续不依赖它的工作。
- 候选来源多且原文远多于所需结论时，尽早委托只读探索。说明目标、范围与交付格式，返回结论、路径行号和可信度，不修改仓库。
- 等待已委托探索结果时不重复检索其范围或读取仓库文件；收到结果后只做尚未解决问题的少量核对。
- 最终只保留判断所需证据，不粘贴长篇原始结果或无关日志。

## 交流与交付

- 使用简单、准确、完整的中文词语。禁用“落地”“钉死”“对齐”等黑话，不用“栈”描述技术或模型组合。
- 避免先否定再转折的对照句式、模板套话、空泛赞美和重复概述；不在回答开头结尾添加总结性套话。
- 只给符合搜索条件的结果，不列已排除内容。图示需要时使用 Mermaid，不使用 ASCII Art。
- 跨电脑交接必须携带 [发布流程](../../docs/release/合并与部署流程.md) 和入口，明确源码、产物、验证、部署与未完成项各自状态。
