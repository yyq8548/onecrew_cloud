# 最简单版本的基础流程

当前优先级：本地基础功能，线上环境与上架材料暂缓。用户选择以这台 Mac 作为当前及后续部署主机，主服务原生运行、4B 使用 Metal，搜索浏览器沿用已有 Docker 环境。商品、平台、粉丝范围，默认共寻找 10 位 KOL；四平台范围保持不变。Mac 启动和独立数据目录见 [Mac 运行](MACOS.md)。

## Gmail 本地实现

复用现有 AccessGmailProvider、GmailBulkRepository、GmailBulkWorker 和 Gmail 回执验证。店铺成员完成 OneCrew 配对后授权 Gmail，选择已保存的联系方式或输入收件人，填写主题和正文，先保存预览，再明确确认发送；支持暂停、继续待发邮件、取消和回执查询。重启后暂停未完成批次，未知结果不自动重发。

每位店铺成员通过已验证的 Access 映射使用独立邮件数据库；完整 Google refresh token 留在 Access，Cloud 加密保存本应用安装凭据。卸载即时停用并排空，店铺数据删除覆盖邮件数据库。Lite 原目录不变。

2026-10-25：已在独立 Cloud Mac 实例复用原本机端口配对及邮件模块，通过真实账号授权，完成用户明确批准的一封自发自收测试邮件，批次 completed、单封 sent，Gmail 内容回读通过。此轮未修改公司代码；原其他邮箱连接保留。当前 Mac 类型检查、邮件相关 17 项检查和本机页面构建通过。邮件输入规则、预览确认和未知结果不重发保持原样，见[验收证据](../handoff/EVIDENCE.md)。

当前 Mac 本机 Gmail 流程可复用公司现有 Access/Sync，Sync Linux 草稿不属于当前部署范围。Shopify 远程商家网页授权仍需 Access HTTPS 回调和配对页 CSP 补充，保持待审批；实际 Shopify 成员绑定、远程网页完整授权及卸载联调尚未验收，见 [公司改动范围](ACCESS-CLOUD-APPROVAL.md)。

## 重现入口

使用现有本地验证数据的独立副本，运行已批准的免费 4B Metal 服务，再执行：

```sh
ONECREW_MODEL_RUNTIME=macos-metal ONECREW_MODEL_SIZE=4b node development/cloud/check-workflow.mjs <独立数据目录> <真实商店公开商品JSON> <商品页面URL> youtube 10000 1000000
```

商品 JSON 是实际公开 `/products/<handle>.json` 的响应，必须含真实 `product.id`、`title`、`body_html`、`updated_at`，不能填写占位商品。脚本使用已有本地安装记录作为存储归属，不提供产品的身份绕过；不创建虚构平台响应。

脚本默认完整执行，检查有评分的 Library 推荐、模板和关闭重开；未满足时明确失败并保存实际状态。最后一个可选参数为已有 Campaign ID，可恢复同一任务而保留材料。Ctrl+C 会请求停止并等待当前工作排空。

验证已有模板更换商品时，在上述命令末尾追加 `--template-id <真实已保存模板ID>`，使用不同的真实商品 JSON 和页面 URL；平台与粉丝范围必须与模板一致。该选项与续跑 Campaign ID 互斥，额外核对新商品快照、条件继承和模板请求幂等。

取消的真实最小检查无需模型：

```sh
node development/cloud/browser/check-read-cancel.mjs <独立数据目录>
```

不要上传私有数据库、主密钥或浏览器快照。换电脑准备方式见[交接入口](../handoff/README.md)。
