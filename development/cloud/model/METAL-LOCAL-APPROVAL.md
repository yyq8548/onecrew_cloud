# 本地模型 GPU 验证审批

状态：用户已批准，本地运行入口和真实组件验证已完成。官方运行包、权重及版本已核验，实际 37/37 层加载到 M1 GPU；四平台关键词约 8.1 秒，三项完整证据评分约 23.7–24.5 秒。具体证据见 [模型验证记录](README.md)。粉丝超上限正确排除，但最高分理由仍不足，批量性能与模型质量尚未通过。验证结束后模型进程已停止。

当前电脑为 Apple M1、16 GiB 内存。Docker 模型配置固定为 CPU 推理，完整证据下的两次评分约 228、234 秒；原方案的单条评分 P95 目标为 30 秒。当前请求没有重复附带同一段证据，继续压缩规则不能据此保证达到目标。

已在这台电脑上使用 llama.cpp 的 macOS Metal GPU 推理进行本地验证。官方 [构建说明](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md#metal-build)确认 Metal 使用 GPU；[b11804 发布页](https://github.com/ggml-org/llama.cpp/releases/tag/b11804)提供 Apple Silicon 包，提交 `c7fc509` 与当前 Linux 容器报告一致。单样本加速结果已记录，批量性能与质量须继续实测。

批准后的具体范围：

1. 官方 macOS arm64 运行包放在本仓库受忽略的 `.scratch` 目录，记录来源、版本与摘要；使用现有 Qwen3-4B Q4_K_M 权重，不重新购买或更换模型，不全局安装软件。
2. 在 `development/cloud/model/` 增加一个本地启动入口，复用 HTTP 接口、8192 上下文、单并发、非思考模式及已有检查脚本。模型监听 `127.0.0.1:8789`，启用 GPU，检查期间停止原 CPU 模型容器，结束后关闭进程。
3. 验证实际 GPU 加载、四平台关键词，以及同一完整真实材料的相关与无关商品评分。保留原结果结构、证据审核、粉丝条件代码和规则；记录速度、输出与资源占用。运行方式写入模型身份，避免沿用 CPU 评分缓存。
4. Linux 浏览器与服务继续使用当前 Docker 配置；仅将本地模型验证增加 Metal 运行方式。测试结果不替代 Linux、Shopify、真实账号、批量质量或生产环境验收。正式上架仍需持续运行的云端服务。

只修改 onecrew_cloud，不修改 Lite、Access、Sync，不购买服务。原 Linux CPU 配置和 4B/8B 权重保留。
